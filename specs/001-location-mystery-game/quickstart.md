# Quickstart and Validation Guide

## Prerequisites

- Node.js 22以上（自動テスト用）
- Python 3（ローカル静的サーバー用）
- iOS Safari実機、Android Chrome実機
- 位置情報を利用できるHTTPSのプレビュー環境（現地試験用）

実装は `docs/mystery-develop/` 内に置き、`file://` ではなくlocalhostまたはHTTPSで開く。

## Local Run

```powershell
python -m http.server 8000 --directory docs/mystery-develop
```

`http://localhost:8000/` を開く。このURLは通常開発モードで、公開用のService WorkerとMIRA専用キャッシュを使用しない。以前のオフライン試験が残っている場合は、このアプリの登録とキャッシュだけを自動整理し、必要なら1回だけ自動再読込する。PlayerStateは保持する。

コンテンツ、JavaScript、CSS、画像を変更した後、キャッシュ名や公開版を変更せずブラウザの通常再読込を1回行い、最新版が表示されることを確認する。強制再読込やブラウザデータの手動削除は通常の開発手順に含めない。

オフライン動作を確認するときだけ `http://localhost:8000/?sw=1` を開く。初回表示で注意事項、音声確認、必須素材の準備状況が表示され、準備完了後だけ本編を開始できることを確認する。

## Automated Checks

```powershell
node --test docs/mystery-develop/tests
```

以下を自動検証対象とする。

- JSON契約、ID一意性、参照整合性、4地点・4問・4パーツ
- 章と画面の状態遷移、順序飛ばし防止、再視聴時の状態不変
- UNIVERSE、5997、HOLESの表記正規化とMIRA並べ替え
- 現在Spotだけの距離判定と到着確認ボタン
- 音声キューの非割込み、bridge優先、既聴・再開位置
- PlayerState保存、復帰、リセット、公開版互換判定
- 必須・任意素材の分類とキャッシュ版整合性
- `development | offline-test | production` の実行モード判定
- 現在のアプリ登録と `mira-signal-` キャッシュだけを整理し、PlayerStateと他キャッシュを維持すること

## Browser Validation

### 通常進行

1. 新規状態でQ1〜Q3、庭園到着、MIRA認証、エンディングまで進む。
2. 各地点でGPS経路と到着確認ボタン経路を別々に確認する。
3. 各正解後にR、A、M、Iが1度だけ追加されることを確認する。
4. 所要時間が歩行約20分、全体30〜40分に収まるか記録する。

### オフライン完走

1. ローカルでは `http://localhost:8000/?sw=1` を開き、オンラインで必須素材の準備完了まで待つ。
2. Service Workerがページを制御していることを確認して再読込する。
3. オフラインにし、地図タイルがなくても方向説明と現在目的が読めることを確認する。
4. 字幕経路で全問とエンディングまで完走する。
5. 任意音声の失敗が開始を妨げず、必須素材不足では開始できず再試行できることを確認する。

### 開発モード切替

1. `?sw=1` で必須素材を準備し、任意の地点まで進めてPlayerStateを保存する。
2. コンテンツまたは画像を変更する。公開版とキャッシュ名は変更しない。
3. クエリなしの `http://localhost:8000/` を開く。
4. 必要な自動再読込が1回以内に完了し、変更後の内容が表示されることを確認する。
5. 進行状態が手順1の状態から継続し、同一オリジンに用意した `mira-signal-` 以外の検証用キャッシュが残ることを確認する。
6. `?sw`、`?sw=true`、`?sw=0` が通常開発になり、`?sw=1` だけがオフライン試験になることを確認する。
7. HTTPSの公開プレビューではクエリ値に関係なく本番用オフライン動作が有効で、参加者画面に切替UIがないことを確認する。

### 復帰と公開版

1. Q2完了後に再読込・ブラウザ再起動し、次区間から30秒以内に再開する。
2. 「新しく始める」は確認前に状態を残し、確認後だけ初期化することを確認する。
3. fixtureで互換版と非互換版を切り替え、互換移行または新規開始案内を確認する。

### 端末差とアクセシビリティ

1. iOS SafariとAndroid Chromeで位置許可拒否、音声再生拒否、画面復帰を確認する。
2. 振動がない環境でも効果音・視覚演出が提示されることを確認する。
3. Q4をタップだけで操作し、色覚に依存せず現在順が読めることを確認する。
4. 問題画像の拡大、代替テキスト、字幕、屋外日中のコントラストを確認する。

## Field Gate

公開前に現地測量で4地点の座標、順序、半径、安全な停止場所、代替経路を確定する。通常、速解き、全ヒントの3条件を複数端末で実歩行し、危険地点での操作誘導がないこと、GPSと到着確認ボタンの両方で完走できることを記録する。Q1は完成図版と解法を第三者テストしてから本素材へ差し替える。
